# Support/privacy mailbox operations — proposed owner checklist

10 October 2026 (Asia/Jakarta). Official mailbox **komprexo.support@gmail.com**. **PROPOSED / OWNER ACTION REQUIRED**, not a claim of implemented Gmail controls or current retention. No Gmail account was accessed, inspected or modified; no message was sent.

| Control | Proposed operation / evidence owner must confirm |
|---|---|
| Authorized access | Identify the legal operator and each authorized support helper privately; least privilege and periodic access review. Do not put personal names, recovery contacts or credentials into public source. Record access roles privately. |
| Strong authentication | Use unique strong password/password manager and Google two-step verification, preferably security keys/passkeys where supported. Never share passwords/codes; review active sessions/app passwords/third-party access. These settings are NOT VERIFIED. |
| Recovery | Secure recovery channels and backup codes; restrict and test owner recovery without publishing private contacts. Remove former helper access. Don't send recovery secrets by support email. |
| Minimum information | Ask app/Android version, device model, workflow/format/target and sanitized error. Prefer synthetic reproduction over personal photo. No default collection of identity documents, birthdate, address, password, OTP, purchase token, full card/bank data or Google account password. |
| Voluntary personal information | Mail sender/address/message is personal information. Limit access/use to support/privacy handling, not advertising or profiling. Explain who handles messages and provider role in approved public policy. No promise that emailing support is anonymous. |
| Attachments | App attaches no images automatically. Discourage personal photos/documents/EXIF/unredacted payment screenshots. Request attachments only when necessary, with consent and redaction; do not open unknown links/macros, forward broadly or paste into public issues/AI tools. Remove unnecessary received copies according to adopted policy. |
| Purchase/refund help | Direct user to owning Play account, restore, official Play refund process; pending isn't activated. No guaranteed refund/time. Do not request card credentials or tokens. If proof is genuinely necessary, agree the minimum redacted evidence and lawful handling first; default to official Google process. No Console action performed. |
| Deletion/privacy requests | Acknowledge using the same channel; verify request control with proportionate minimal information, not default identity-document collection. Determine records controlled by operator vs Google/receiver. Carry out approved deletion/access/correction process and preserve legally mandatory records with explanation. Qualified adviser determines statutory deadlines; none invented here. |
| Retention proposal | **For approval only:** delete closed support thread content after 90 days; delete received troubleshooting attachments within 30 days after case closure, earlier when unnecessary. Open cases reviewed regularly; any legal/security hold must be justified, minimal, access-restricted, reviewed and communicated where required. No indefinite retention by default. Actual practice UNKNOWN; periods not adopted and must not appear as factual public promises. |
| Mail provider/copies | Document Gmail/other provider trash/backups/security retention and any forwarded copies; do not promise instantaneous deletion of every provider backup. Owner confirms actual provider controls and deletion completion. Vendor retention UNKNOWN until verified. |
| Disclosure/rights | After approval/adoption, synchronize support retention/contact/request wording in all 5 languages and offline/web. Developer privacy contact remains official mailbox; qualify limitations and preserve mandatory rights. |
| Incident response | Privately record report, stop unnecessary sharing, secure compromised access and assess applicable notice duties with qualified advisers; no unsupported universal 72h/other deadline claim. Avoid publishing user contents. |
| Decision record | Owner records adopted controls/retention, responsible roles, review dates and qualifications privately; repo stores only approved non-sensitive policy facts. Current checklist is preparation, not proof of operation. |

Public drafts correctly leave mailbox retention/deletion practices unresolved. App's ACTION_SENDTO only opens user's mail client without attachment. User decides whether to send; received email is processed by mailbox operator/mail providers separately from on-device image processing and GitHub Pages visitor logs.
